# gfx1151 deterministic FP64 expert weighted reduction

Status: **accepted and enabled**. Every result below is measured on gfx1151; no estimated performance numbers are reported.

## Target and implementation

The post-expert prefill path previously issued separate padded-row gather, router-weight multiplication, unordered `index_add_`, and FP32-to-BF16 conversion kernels. The exact 32,768/+1 trace ranked `indexFuncLargeIndex` alone at 160 calls and 1,130.480012 ms. Its atomic accumulation order was nondeterministic: fresh baseline processes produced different Pair-B greedy tokens, including token 0.

`kernels/gfx1151/moe/expert_weighted_reduce_top8_fp64_gfx1151.s` fuses padded expert-row gather, eight router-weight products, reduction, and BF16 conversion. Each gfx1151 wave handles contiguous hidden columns for one token. It scalar-loads the eight row indices and weights, issues eight coalesced FP32 loads, converts each operand to FP64, accumulates eight `v_fma_f64` operations in fixed slot order, converts once to FP32, then stores BF16 RNE. This implements the high-precision oracle order rather than attempting to reproduce unordered atomics.

The code object is gfx1151 wave32 with 40 VGPR, 44 metadata SGPR, zero LDS, zero scratch, and no spills. rocprofv3 reports 40 VGPR / 128 allocated SGPR at dispatch. Before/after evidence is in `docs/notes/disassembly/expert-weighted-reduce-pairwise-gfx1151/` and `docs/notes/disassembly/expert-weighted-reduce-top8-fp64-gfx1151/`.

## Correctness gates

- Controlled 128-token and 8,192-token shapes: zero BF16 bit mismatches against FP64 products and sum, followed by FP32 and BF16 RNE.
- Real checkpoint, exact 210-token uncached request: all 40 MoE layers independently compared the raw output against the same high-precision oracle; every layer reported zero BF16 bit mismatches.
- Exact uncached real-checkpoint outputs: 8,192/+1 returned token 220; 32,768 Pair-A returned 248045; Pair-B returned 220 in both an ordinary process and a separate rocprofv3 process.
- HIP graph capture/replay with stable pointers: zero replay-versus-eager and zero replay-versus-FP64 BF16 bit mismatches. The first standalone probe that cached the pre-capture stream produced an empty graph and was discarded; the production bridge resolves the current stream at launch.

## Full-request rocprofv3 evidence

Both traces are exact 32,768-input/+1-output, uncached, graph disabled, dFlash disabled on gfx1151.

| Path | Calls | Total GPU ms | Mean us | Trace-wall share |
|---|---:|---:|---:|---:|
| Old unordered `indexFuncLargeIndex` reduction | 160 | 1,130.480012 | 7,065.500 | 2.673% |
| Raw FP64 fused reduction | 160 | 462.722462 | 2,892.015 | 1.254% |

The directly replaced reduction falls 59.067% (2.443106x). Because the raw dispatch also removes adjacent gather, weighting, conversion, and allocation launches, full trace kernel launches fall from 38,203 to 33,820. Total process-start kernel time falls from 27,035.351 to 24,566.360 ms and positive launch gaps from 15,264.835 to 12,326.289 ms. The new trace contains 33,820 launches over 36,888.693 ms: 66.596% kernel occupancy and 33.415% positive-gap occupancy. `hipMemcpyWithStream` remains the dominant CPU API with 11,974 calls and 23,832.128 ms inclusive CPU duration; this overlaps queued GPU execution and is not added to kernel time.
