# gfx1151 BF16 decode projections: accepted LM-head replacement

Date: 2026-07-31

Target: AMD Ryzen AI Max+ PRO 395 / Radeon 8060S, `gfx1151`, wave32.

Status: the exact batch-1 LM-head replacement is accepted and enabled by the
Netra launch script. This is one completed projection in the larger decode
optimization mission; it does not mark the full mission complete.

Every number below is measured on `gfx1151` unless explicitly marked
estimated. The checkpoint remains model-native MXFP4 with a model-native BF16
LM head; no alternative checkpoint quantization was used.

## Why rocBLAS was slow at M=1

The request inventory placed model-native BF16 rocBLAS projections at 761.829
ms of 1559.064 ms total GPU time for exact eager 1-input/32-output serving:
48.9% of GPU time. The LM head alone cost 8.48--8.52 ms per decoded token.

The exact rocBLAS LM-head symbol is a generic
`MT128x128x32_MI16x16x16` Tensile kernel. Its measured `gfx1151` properties
were:

- 256 allocated VGPRs, 128 allocated SGPRs, 50 KiB LDS, no scratch;
- 12.45% occupancy and 7.99 mean waves per active CU;
- 3730 VALU instructions per wave and 7760 waves per dispatch;
- 496876 KiB fetched, 240 KiB written, 0.50% L2 hit rate;
- 94.11% memory-unit busy.

Disassembly shows a generic 128x128 tile, 160 BF16 WMMA instructions in the
static body, broad waits, and repeated barriers. Padding a one-row problem into
that implementation produces severe VGPR/LDS occupancy loss and unnecessary
matrix-tile work.

## Raw assembly design

`bf16_lm_head_decode_wave4_gfx1151` is fixed to M=1, N=248320, K=2048 and the
real row-major `[248320,2048]` BF16 weight layout. One wave32 computes four
logits; one 256-thread workgroup contains eight waves. Each lane loads one BF16
activation pair and four coalesced weight pairs per K step, accumulates with
`v_dot2_f32_bf16`, performs wave reductions with `ds_bpermute_b32`, rounds to
BF16, and stores four adjacent logits.

Measured `gfx1151` properties:

- 18 VGPRs requested by metadata, 24 in the profiler allocation granule;
- 128 SGPRs in the profiler allocation granule, zero LDS, zero scratch;
- 92.82% occupancy and 60.29 mean waves per active CU;
- 384 VALU instructions per wave and 62080 waves per dispatch;
- 496883 KiB fetched, 295 KiB written, 1.11% L2 hit rate;
- 99.91% memory-unit busy.

The nearly identical fetch volume confirms that the accepted kernel is now
close to the unavoidable weight-read floor. Its main gain is eliminating the
generic matrix tile, 50 KiB LDS allocation, barriers, and 256-VGPR occupancy
limit. A direct dependency-stall metric is not exposed by the installed
`rocprofv3` metric set on `gfx1151`; this is recorded as unavailable rather
than estimated.

## Kernel timing and correctness

Real checkpoint, 10 independent BF16 activations, model-native rocBLAS
reference, 30 HIP-event timing samples per variant:

| `gfx1151` result | rocBLAS baseline | raw assembly |
|---|---:|---:|
| HIP-event median | 8.522 ms | 6.476 ms |
| HIP-event p90 | 8.762 ms | 6.923 ms |
| Median speedup | 1.000x | 1.316x |
| Maximum absolute difference | reference | 0.015625 |
| Maximum BF16 bit mismatches / 248320 | reference | 291 |
| Argmax agreement | reference | 10/10 |

The difference is a legal accumulation-order difference against the existing
BF16 output path. The acceptance gate is stronger at serving level: all 20
paired eager/full-graph requests produced identical deterministic output-token
sequences.

Five isolated HIP graph replays used stable weight, activation, and graph-pool
output pointers. All five matched the rocBLAS argmax. The module registry was
initialized before capture; the raw launch does not query the device, allocate,
synchronize, resolve a symbol, inspect a tensor, or change registration state.
A process-start `rocprofv3` full-graph trace independently recorded five raw
LM-head dispatches in the captured/replayed server process. Their measured
median GPU duration was 6.557 ms, with 24 VGPRs, zero LDS, zero scratch, grid
1986560, and workgroup 256.

The final shared-library symbol check preserved every previously exported
`netra_*` symbol and added only `netra_bf16_lm_head_decode`. The kernel uses a
24-byte, 8-byte-aligned three-pointer kernarg and the caller's HIP stream.


## End-to-end serving A/B

Each cell is the median of five uncached, deterministic, exact-token requests.
Timing is measured host HTTP end-to-end wall time. TTFT is explicitly not
measured by these non-streaming acceptance requests.

| graph path | exact tokens | rocBLAS | raw assembly | latency reduction | effective output rate |
|---|---:|---:|---:|---:|---:|
| eager | 1 input + 32 output | 1783.291 ms | 1724.918 ms | 3.27% | 17.94 -> 18.55 tok/s |
| eager | 210 input + 128 output | 7418.291 ms | 7182.064 ms | 3.18% | 17.25 -> 17.82 tok/s |
| full decode graph | 1 input + 32 output | 1796.389 ms | 1733.242 ms | 3.52% | 17.81 -> 18.46 tok/s |
| full decode graph | 210 input + 128 output | 7470.211 ms | 7209.503 ms | 3.49% | 17.13 -> 17.75 tok/s |

All requests reported exactly zero cached input tokens. dFlash was disabled.
Full-graph capture used tiers 1/2/4/8/12/16. Measured graph construction was
3.04 s and 0.16 GB for the baseline versus 2.94 s and 0.16 GB for the raw
kernel; no extra graph break or launch was introduced.

After enabling the accepted path by default in `launch.sh`, a fresh exact
210-input/+1-output uncached smoke completed in 1078.194 ms and returned one
token (`46`). Weight loading took 9.25 s.

## Negative results

- A DPP/permlanex reduction prototype was rejected after measured random-input
  error reached approximately 1.62 maximum absolute difference. The accepted
  kernel uses the correct DS butterfly reduction.
- Raising bounded safetensor loading from two to eight threads was rejected.
  On Netra's 16 GiB host-memory limit, the server was killed at shard 0/26
  because pending shard buffers exceeded available memory.
- The accepted loader remains two threads with mmap disabled and bounded shard
  lifetime. Historical shard loading was 731--740 s; measured current loading
  is 9.13--10.17 s, including 9.49--9.67 s in this A/B.

## Remaining BF16 projection queue

These are measured trace aggregates per decoded token on `gfx1151`, not
estimates. They remain targeted for exact-shape raw assembly:

| rank after LM head | shape/family | measured cost per token |
|---:|---|---:|
| 1 | full-attention QKV, N=9216 K=2048 | 6.025 ms |
| 2 | shared-expert gate+up, N=1024 K=2048 | 4.146 ms |
| 3 | router, N=256 K=2048 | 3.108 ms |
| 4 | attention output, N=2048 K=4096 | 2.227 ms |
| 5 | shared-expert down, N=2048 K=512 | 1.405 ms |

The LM-head result demonstrates that rocBLAS is a baseline, not a boundary.
The next replacements will specialize these real M=1 shapes and will be kept
only after the same correctness, HIP-event, `rocprofv3`, eager, and graph gates.
