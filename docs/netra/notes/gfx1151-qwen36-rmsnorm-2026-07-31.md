# Qwen3.6 decode RMSNorm on gfx1151 — 2026-07-31

All results are for the AMD Ryzen AI Max+ PRO 395 (`gfx1151`) with the real
`/root/models/qwen36-sgl-mxfp4` checkpoint. GPU claims use HIP events or
rocprofv3. Serving numbers are measured host end-to-end HTTP time.

## Scope and naming

This is a Qwen3.6 optimization. SGLang happens to implement Qwen3.6's
`norm(x) * (1 + weight)` operation in its internal `GemmaRMSNorm` class. No
Gemma checkpoint, model configuration, or weights are used. Netra-facing files,
symbols, flags, and reports use `qwen36_*` names.

The accepted specialization covers contiguous M=1, N=2048 BF16 input and BF16
weight. The fused variant rounds `input + residual` to BF16 before computing the
variance, matching SGLang's model-native residual semantics.

## Implementation

- Raw assembly: `kernels/gfx1151/norm/qwen36_rmsnorm_decode_gfx1151.s`
- Symbols: `qwen36_rmsnorm_decode_gfx1151` and
  `qwen36_fused_add_rmsnorm_decode_gfx1151`
- Launch: one 256-thread wave32 workgroup, 32-byte fixed LDS in metadata, no
  scratch, 32 VGPRs and 13 SGPRs in the code-object metadata
- C ABI: `netra_qwen36_rmsnorm_decode` and
  `netra_qwen36_fused_add_rmsnorm_decode`
- Fallback: `SGLANG_NETRA_DISABLE_QWEN36_RMSNORM=1`
- HSACO SHA-256:
  `5816518c4026554d3b8943a42c388a6b90b46b6b8f9a17974c716868e8349d7f`

The runtime preloads and resolves both functions before capture. The launch path
uses the caller's current HIP stream and performs no allocation, lookup, device
query, synchronization, or registration mutation.

## Correctness gates

- Isolated deterministic driver: standalone 2048/2048 bit-exact, fused
  2048/2048 bit-exact, and residual 2048/2048 bit-exact.
- Python bridge: 20/20 randomized standalone cases and 20/20 randomized fused
  cases bit-exact against native FP32 accumulation with BF16 output; all residuals
  bit-exact.
- Graph replay: bit-exact against eager for output and residual.
- Real checkpoint: all six interleaved eager serving runs produced identical
  input hashes, 32 output token IDs, and decoded-text hashes.
- Full graph versus eager: identical input hash and identical 32-token output hash
  `43448edd8a4056c366390bc84b8d544fa4612a281634a60ce19057ae87561017`.

## Streamed decode timing

Three exact 1-input +128-output uncached streamed requests measured 35.851,
35.846, and 35.804 output tokens/s. Median TTFT was 61.923 ms, median decode
interval for the remaining 127 tokens was 3542.942 ms, and median host E2E was
3604.391 ms. The measured sustained non-speculative decode rate is therefore
35.846 tokens/s on gfx1151.

## Full graph

rocprofv3 recorded 32 `hipGraphLaunch` calls and the raw norm kernels inside the
graph. One unprofiled full-graph request measured 923.732 ms versus a same-seed
eager request at 921.199 ms, a 0.28% difference within single-run noise. Graph
correctness and capture safety pass; no graph speedup is claimed from this pair.

## Disassembly and tooling result

The candidate disassembly and metadata are under
`gfx1151-qwen36-rmsnorm-disassembly-2026-07-31/`. The native baseline is not a
single kernel: it is a dynamically selected chain of generic PyTorch kernels.
Their exact rocprofv3 names, resource data, counts, and durations are preserved in
`baseline-chain.json`.

Netra's installed `roc-obj-ls` cannot run because Perl `File::Which` is absent.
Direct `clang-offload-bundler` scanning of the 174 MiB `libtorch_hip.so` did not
complete and was interrupted. No package was downloaded, and no unverifiable
"before disassembly" was fabricated. The raw candidate disassembly is complete;
native fat-binary extraction remains an explicit tooling gap.
